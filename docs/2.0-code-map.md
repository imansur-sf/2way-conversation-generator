# 2.0 Code Map

The original interactive builder remains available during the 2.0 rebuild, so it is deliberately not replaced by a second, incomplete channel simulator. New work belongs in the modules below.

| Area | Location | Responsibility |
| --- | --- | --- |
| Hosted API and AI job lifecycle | `server.js` | Request validation, safe website retrieval, Gemini calls, bounded jobs, retry behavior, transient duplicate-draft caching, and health metrics. |
| Inherited simulator core | `interactive-simulator-builder.html` | Existing editable scenarios and channel renderers. It remains the compatibility layer while 2.0 is validated. |
| 2.0 workspace shell | `assets/v2-modern.js` / `assets/v2-modern.css` | Navigation, keyboard shortcuts, focus mode, flow map, scenario QA, image-state feedback, AI generation controls, progress UI, accessibility hydration, and the modern visual system. |
| Accessible status announcements | `assets/v2/live-region.js` | Reusable polite live-region announcer. |
| Local scenario recovery | `assets/v2/scenario-backup.js` | IndexedDB mirror and one-time recovery of local scenarios. |
| Regression and acceptance checks | `test/` and `scripts/` | Unit, browser/accessibility/export, hosted health, and live Gemini acceptance checks. |

## Migration rule

Do not add new functionality to the inherited inline builder unless it has to preserve a current channel behavior. Add reusable UI, storage, and test code under `assets/v2/`, then progressively move isolated core capabilities there behind the existing scenario data contract. This keeps the 2.0 rebuild testable without destabilizing the original app or the downloaded HTML experience.

## Generation contract

AI generation converts the prompt into a structured contract before the finished draft is accepted. The contract covers named participants, subjects, handoffs, the requested opening sender, explicitly quoted and ordered turns, and an optional exact message total. The server validates the returned draft, deterministically preserves scripted turns, corrects the opening sender, and fills a stated message-count gap before it reaches the review UI. The review surface shows each contract check so a user can see what will be applied.
